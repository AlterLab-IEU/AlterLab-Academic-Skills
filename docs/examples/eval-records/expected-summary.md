## Selection rule

1. A case inside a behavioral-regrade record supersedes the same case in the record it was regraded from (`regraded_from` = that file's name; a source in the regrade's own directory is preferred when several inputs share the name).
2. Collect-only runs (kind `behavioral`, `collect_only: true`) called no judge: they are ungraded and never counted.
3. With --skills-root, cases of skills that are no longer in the suite are left out.
4. Only runs that recorded namespace confinement (`isolation.confinement.mode` = `namespace`) and a clean working tree (`repo_dirty: false`) are eligible; a run that recorded neither is not eligible.
5. With --require-ancestor COMMIT, only runs whose `repo_commit` contains COMMIT (git merge-base --is-ancestor) are eligible; an unverifiable commit is not.
6. Per case_id, the eligible run with the LATEST `finished_at` (else `started_at`) is counted.
7. Eligible runs tied at that time with identical outcomes and methodology: the one from the lexicographically first file is counted, the others are duplicates. Tied runs that disagree are an unresolved conflict, and the case is not counted.
